# FlavorFit — клиент

Считает дневную норму КБЖУ по замерам тела и цели, подбирает под неё рецепты, собирает список продуктов на закупку.

Стек для приложения такого размера избыточен, и это осознанно. REST плюс пара страниц закрыли бы задачу быстрее. Я взял GraphQL с кодогенерацией, Apollo и SSR, потому что хотел разобраться в них там, где они действительно решают проблему, а не в примере из документации.

Сервер: **[FlavorFit-backend](https://github.com/muhammad2008nur/FlavorFit-backend)**

## Токены

`localStorage` — самое частое место для JWT и самое плохое. Любой скрипт на странице его читает: подключённая аналитика, зависимость, которую подменили в npm, вставка через XSS. Токен уходит целиком, и вы об этом не узнаете.

Здесь их две штуки, обе в куках с `httpOnly`. JavaScript их не видит вообще — браузер сам прикладывает к запросам. Access живёт час, refresh три дня.

Когда access протухает, сервер отдаёт `UNAUTHENTICATED`. `ErrorLink` в цепочке Apollo перехватывает эту ошибку, запрашивает `newTokens` и повторяет запрос, который упал. Пользователь ничего не замечает.

Отдельный инстанс Apollo для SSR — не перестраховка. Один клиент на процесс Node означает один `InMemoryCache` на всех: профиль первого пользователя уезжает второму. Сейчас от этого спасает `fetchPolicy: "no-cache"`, но это костыль, а не решение.

## Известные проблемы

Обновление токенов ломается на параллельных запросах. Пять запросов получают `UNAUTHENTICATED` одновременно — пять `newTokens` уходят разом, куки перезаписывают друг друга. Лечится одним разделяемым промисом, чиню.

Валидация форм разбросана по компонентам инлайном. Работает, но при добавлении третьей формы это станет больно.

Тестов нет.

## Структура

```
src/
├── app/          # роутинг, провайдеры, глобальные стили
├── features/     # auth, layout, profile
│   └── auth/
│       ├── ui/
│       └── hooks/
└── shared/       # переиспользуемое между фичами
    ├── api/          # сгенерированные типы GraphQL
    ├── lib/apollo/   # клиент, links
    ├── config/
    └── utils/
```

`features` тянут из `shared`, обратно — нет, друг о друге не знают. Смысл в том, что любую фичу можно вырезать целиком, не разбирая, за что ещё она держится.

## Запуск

Нужен Node 20+ и поднятый сервер.

```bash
git clone https://github.com/muhammad2008nur/FlavorFit.git
cd FlavorFit
npm install
cp .env.example .env
npm run dev
```

`localhost:3000`.

| Переменная | Описание |
|---|---|
| `NEXT_PUBLIC_GRAPHQL_URL` | адрес GraphQL-сервера, например `http://localhost:4000/graphql` |
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY` | публичный ключ Cloudflare Turnstile |

Типы запросов руками не пишутся — `npm run codegen` собирает их из схемы сервера. Гонять после каждой правки схемы, иначе TypeScript будет врать.
